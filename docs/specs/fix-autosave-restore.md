# プロジェクト復元・自動保存バグ修正 仕様書

## 概要

マイページからプロジェクトを再オープンしたとき、スライド生成済みの状態に正しく復元されず、エラーが発生する問題を修正する。

## 背景・目的

現状、ユーザーがスライド生成まで進めてマイページに戻り、再度プロジェクトを開くと:
- スライドではなくアウトライン段階に巻き戻される
- そこから操作するとエラーが連鎖する
- 自動保存が正しく機能していないため、作業が失われる

ユーザーが安心してプロジェクトを中断・再開できるようにすることが目的。

## 原因分析（調査済み）

### 原因1: ページ離脱時のレースコンディション
- **場所**: `app/page.tsx` 509-512行目付近
- **内容**: auto-save は `state.step` 等の変更で発火するが、ユーザーがすぐにダッシュボードに遷移すると保存完了前にアンマウントされる
- **対策**: ページ離脱前に保存を確実に完了させる（beforeunload / router イベント）

### 原因2: バックエンド復元失敗のサイレントエラー
- **場所**: `app/page.tsx` 424-450行目付近
- **内容**: `/api/restore-project` が失敗してもエラー表示されない。バックエンドのジョブが存在しない状態でフロントだけ進む
- **対策**: 復元失敗時にユーザーに通知し、リトライまたはフォールバック処理を入れる

### 原因3: スライドプレビュー未保存によるステップ巻き戻し
- **場所**: `app/page.tsx` 424行目付近
- **コード**:
  ```typescript
  if (data.step >= slideCompleteStep && restoredPreviews.length === 0) {
    adjustedStep = slideGenStep; // スライド生成前に巻き戻し
  }
  ```
- **内容**: `settings.slidePreviews` が空配列のままだとスライド生成済みでもステップが巻き戻される
- **対策**: スライド生成完了時に slidePreviews を確実に保存する。復元時は再生成のオプションも提供する

### 原因4: バックエンドが常に step=5 で復元
- **場所**: `backend/main.py` 2596行目
- **コード**:
  ```python
  jobs[job_id]["step"] = 5  # フロントのステップに関係なく常に5
  ```
- **内容**: フロントが step=6 でも step=8 でも、バックエンドは常に step=5 で復元 → フロントとバックエンドのステップ不整合
- **対策**: フロントから渡されたステップ情報に基づいてバックエンドのジョブステップも正しく設定する

### 原因5: 復元後のデータ検証なし
- **場所**: `app/page.tsx` 453-466行目付近
- **内容**: outline / polished_outline が不完全・破損していてもそのまま復元される
- **対策**: 復元時にデータの妥当性を検証し、不正なら該当ステップまで巻き戻す

## 要件

- [ ] ページ離脱時に未保存データを確実に保存する
- [ ] バックエンド復元失敗時にエラーを表示し適切にハンドリングする
- [ ] スライドプレビューがスライド生成完了時に確実に保存される
- [ ] バックエンド復元時のステップをフロントと一致させる
- [ ] 復元データの妥当性チェックを追加する
- [ ] 既存の自動保存（30秒間隔）は維持する

## スプリント計画

### Sprint 1: 自動保存の信頼性向上
- **対象ファイル**: `app/page.tsx`
- **内容**:
  - ページ離脱前（beforeunload / Next.js router イベント）に保存を実行
  - スライド生成完了時に slidePreviews を即座に保存
  - auto-save のエラーハンドリング強化
- **受け入れ条件**:
  1. スライド生成後にブラウザバック / ダッシュボード遷移しても保存が完了している
  2. slidePreviews が Supabase の settings カラムに正しく保存されている
  3. auto-save 失敗時にコンソールに詳細なエラーが出力される

### Sprint 2: バックエンド復元ロジック修正
- **対象ファイル**: `backend/main.py`
- **内容**:
  - `/api/restore-project` でフロントのステップ情報を受け取り、正しいステップで復元する
  - RestoreProjectRequest に step フィールドを追加
- **受け入れ条件**:
  1. フロントから step=6 で復元リクエストが来たら、バックエンドのジョブも step=6 で初期化される
  2. 復元後のジョブステータスがフロントと一致する
  3. 既存の復元テストが通る

### Sprint 3: フロントエンド復元ロジック修正
- **対象ファイル**: `app/page.tsx`
- **内容**:
  - 復元時にバックエンド失敗をハンドリング（リトライ / エラー表示）
  - 復元データの妥当性チェック追加
  - slidePreviews が空でも不必要にステップを巻き戻さない（再生成オプションを提供）
- **受け入れ条件**:
  1. バックエンド復元失敗時にユーザーにエラーメッセージが表示される
  2. outline データが不完全な場合、該当ステップに適切に戻される
  3. slidePreviews が空でもステップ巻き戻しではなく「スライドを再生成」ボタンが表示される
  4. 正常なデータでの復元が step=6 のまま維持される

### Sprint 4: テスト追加
- **対象ファイル**: `__tests__/`, `backend/tests/`
- **内容**:
  - プロジェクト復元のリグレッションテスト
  - 自動保存のエッジケーステスト
- **受け入れ条件**:
  1. 「スライド生成済みプロジェクトの復元」テストがパス
  2. 「バックエンド復元失敗時のフォールバック」テストがパス
  3. 「ページ離脱時の保存」テストがパス
  4. 既存テストがすべてパス

## 影響範囲

- `app/page.tsx` — メインの状態管理・保存・復元ロジック
- `backend/main.py` — `/api/restore-project` エンドポイント
- `app/dashboard/page.tsx` — 影響なし（プロジェクト一覧表示のみ）
- Supabase スキーマ — 変更なし（既存カラムで対応可能）

## 対象外（スコープ外）

- ダッシュボードのUI変更
- 新規機能の追加
- Supabase スキーマの変更
- 認証周りの変更
