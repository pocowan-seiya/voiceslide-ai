# docs/qa/fixtures/ — 固定音声サンプル管理

## 目的

品質評価・モデル比較を **再現可能** にするため、固定の音声サンプルを管理する。
同一入力を使うことで、モデルやモード間の差を正確に比較できる。

## 命名規則

```
{長さカテゴリ}_{内容の短い説明}_{秒数}.{拡張子}

例:
  short_selfintro_25s.mp3
  medium_product_demo_120s.mp3
  long_tech_lecture_360s.wav
```

### 長さカテゴリ

| カテゴリ | 時間 | 想定用途 |
|----------|------|----------|
| `short`  | 30 秒以内 | 高速スモークテスト、CI での自動検証 |
| `medium` | 1〜3 分 | 標準ユースケース確認、品質ルーブリック採点 |
| `long`   | 5 分以上 | パフォーマンス・タイムアウト・コスト測定 |

## 想定用途別サンプル

| サンプル名 | 用途 | 内容の特徴 |
|-----------|------|-----------|
| `short_selfintro_*` | スモークテスト | シンプルな自己紹介。スライド 2〜3 枚程度 |
| `medium_product_demo_*` | 標準品質評価 | 製品説明。見出し・箇条書き・結論のある構造 |
| `medium_story_*` | 連続性テスト | ストーリー形式。スライド間の流れが重要 |
| `long_tech_lecture_*` | パフォーマンス評価 | 技術解説。スライド 10 枚以上。生成時間・コストの計測用 |

## 管理方法

### Git 管理

- **小さいファイル (< 5 MB)**: そのまま Git 管理に含める
- **大きいファイル (>= 5 MB)**: `.gitignore` に追加し、取得手順をこの README に記載する

### .gitignore の設定（大きいファイル用）

```gitignore
# docs/qa/fixtures/ 内の大きな音声ファイル
docs/qa/fixtures/*.wav
docs/qa/fixtures/long_*
```

### 大きいファイルの取得手順

大きなファイルが `.gitignore` で除外されている場合:

1. チーム共有ストレージ（Supabase Storage の `qa-fixtures` バケット等）からダウンロード
2. または以下のコマンドで生成:
   ```bash
   # 例: ffmpeg でテスト用無音ファイルを生成（パフォーマンステスト用）
   ffmpeg -f lavfi -i anullsrc=r=44100:cl=mono -t 360 -q:a 9 -acodec libmp3lame long_silence_360s.mp3
   ```

## 注意事項

- 音声ファイルの内容は **個人情報を含まない** こと
- 著作権のあるコンテンツは使用しない
- サンプルを追加・変更した場合はこの README を更新する
- 品質ルーブリック採点時は **同一サンプルを全モードで使用** すること
