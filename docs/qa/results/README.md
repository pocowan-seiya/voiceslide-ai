# docs/qa/results/ — 比較 QA 結果の保存

## 目的

モデル・モード間のデザイン品質比較結果を蓄積し、改善の意思決定に使う。

## 保存形式

### ファイル命名規則

```
{日付}_{比較対象}_{音声サンプル名}.md

例:
  2026-05-03_flash-vs-pro_medium_product_demo.md
  2026-05-10_pro-vs-gptimage2bg_short_selfintro.md
```

### 比較対象の略称

| 略称 | モード | 説明 |
|------|--------|------|
| `flash` | flash_standard | Gemini Flash 標準モード |
| `pro` | pro | Pro モード（AI にレイアウト・フォント判断権） |
| `gptimage2bg` | image-background | GPT Image 2 背景生成モード（将来） |
| `gptimage2full` | image-full | GPT Image 2 全面画像モード（将来実験） |

## テンプレート

新しい比較 QA を行う際は以下のテンプレートをコピーして使用する:

- [`template-design-quality-comparison.md`](./template-design-quality-comparison.md)

## 記録する項目

各比較結果には以下を含める:

| 項目 | 内容 |
|------|------|
| 日付 | 実施日 |
| 評価者 | 誰が採点したか |
| 音声サンプル | 使用した固定音声（`fixtures/` 内のファイル名） |
| 比較モード | flash_standard / pro / image-background 等 |
| モデル名・バージョン | 使用した具体的なモデル ID |
| 生成時間 | 各モードでの生成所要時間 |
| API コスト | 推定コスト（ログまたは API レスポンスから取得） |
| 失敗の有無 | タイムアウト、エラー、フォールバック発生 |
| ルーブリックスコア | 10 項目各 1〜5 + 合計 |
| 見た目の所感 | スクリーンショット参照 or テキスト記述 |
| 音声同期の所感 | 動画再生時の同期品質 |
| 復元結果 | 保存→ダッシュボード復元→再生が正常か |
| 結論・推奨 | どのモードが優れているか、改善すべき点 |

## スクリーンショットの保存

- スクリーンショットは `docs/qa/results/screenshots/` に配置
- 命名: `{日付}_{モード}_{スライド番号}.png`
- 例: `2026-05-03_pro_slide03.png`

## 結果の活用

1. **モデル切替判定**: 新モデル/モードが既存を上回るかの根拠にする
2. **リグレッション検知**: コード変更後に同一サンプルで再評価し、スコア低下を検知
3. **ロードマップ判断**: 画像生成モード（GPT Image 2）の投入タイミングを決める
