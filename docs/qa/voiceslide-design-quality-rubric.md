# VoiceSlide Movie — デザイン品質ルーブリック

## 目的

VoiceSlide の生成品質を **定量的かつ再現可能** に評価するための基準。
モデル比較（flash_standard / pro / 将来の画像生成背景モード）の際に共通尺度として使う。

## VoiSlide の品質哲学

> 余白があり、言葉が立つスライド

- 綺麗な1枚絵より、**音声と一緒に連続して見た時の自然さ** を重視する
- テキストは画像生成モデルに任せすぎず、**HTML/CSS テキストとして読める** ことを重視する
- 余白は必要。ただし **余白過多で画面を使えていない状態も減点対象** とする
- GPT Image 2 等の画像生成は最初から全面画像化せず、**背景・キービジュアル実験** として扱う

## 評価項目

各項目を 1〜5 で採点する。3 が「許容」、4 が「良好」、5 が「優秀」。

### 1. Copy Fidelity（文字忠実度）

| スコア | 基準 |
|--------|------|
| 5 | 文字起こしの内容を正確に反映。追加・省略なし |
| 4 | 軽微な言い換えがあるが意味は同一 |
| 3 | 若干の要約はあるが主旨は保持 |
| 2 | 文字起こしにない言葉が追加されている |
| 1 | 内容が大きく逸脱、捏造に近い |

**判定基準**: 文字起こしにない言葉を足さない。要約は許容するが、意味の追加は NG。

### 2. Readability（可読性）

| スコア | 基準 |
|--------|------|
| 5 | 日本語が自然に読め、フォントサイズ・行間が適切 |
| 4 | 問題なく読める |
| 3 | 小さい文字や詰まった箇所があるが読める |
| 2 | 読みづらい箇所が目立つ |
| 1 | テキストが切れている、重なっている、読めない |

**判定基準**: 日本語が読みやすいこと。HTML/CSS テキストとして描画されていること。

### 3. Whitespace（余白）

| スコア | 基準 |
|--------|------|
| 5 | 余白と情報密度のバランスがよく、画面全体を自然に使えている |
| 4 | 余白があり窮屈さを感じない。主役要素も十分大きい |
| 3 | 許容範囲だが、余白不足または余白過多が少しある |
| 2 | 詰め込み感、または余白過多で画面を使えていない |
| 1 | 余白なしで破綻、または中央に小さく寄りすぎて情報量が足りない |

**判定基準**: 余白は必要だが、画面中央に小さく寄りすぎる状態や余白過多は減点する。

### 4. Visual Hierarchy（視覚階層）

| スコア | 基準 |
|--------|------|
| 5 | タイトル・本文・補助要素の優先順位が明確 |
| 4 | 階層が感じられ、重要度の違いがわかる |
| 3 | 最低限の区別はある |
| 2 | 要素が均一で優先順位が不明 |
| 1 | 全要素が同じ大きさ・色で区別できない |

**判定基準**: タイトル・本文・補助要素の優先順位がある。

### 5. Continuity（連続性）

| スコア | 基準 |
|--------|------|
| 5 | 動画として通して見ても一貫したトーン・配色・レイアウトパターン |
| 4 | 概ね統一感があり、違和感は軽微 |
| 3 | 個別には良いが、通して見ると雰囲気が変わる箇所がある |
| 2 | スライドごとにバラバラな印象 |
| 1 | 全くの別テーマが混在している |

**判定基準**: 動画として連続して見た時に違和感がない。

### 6. Audio Fit（音声適合）

| スコア | 基準 |
|--------|------|
| 5 | スライド切替が発話タイミングと完全に合致 |
| 4 | ほぼ合っている（±0.5 秒以内） |
| 3 | 少しずれるが内容の対応は正しい |
| 2 | ずれが目立ち、話している内容と違うスライドが表示される |
| 1 | 音声とスライドが完全にずれている |

**判定基準**: 音声とスライド切替が合う。

### 7. Editability（編集容易性）

| スコア | 基準 |
|--------|------|
| 5 | テキスト編集・スライド追加/削除/並替がスムーズ |
| 4 | 主要な編集操作が問題なく動作 |
| 3 | 編集は可能だが手順が不明瞭 |
| 2 | 編集が一部壊れる、反映されない |
| 1 | 編集不能 |

**判定基準**: 後から修正できる。

### 8. Restore Safety（復元安全性）

| スコア | 基準 |
|--------|------|
| 5 | 保存→復元で完全に同一状態が復元される |
| 4 | 軽微な差異はあるが実用上問題なし |
| 3 | 一部設定が失われるが再設定可能 |
| 2 | 復元時にデータ欠損がある |
| 1 | 復元失敗またはクラッシュ |

**判定基準**: 保存・復元で壊れない。

### 9. Performance（生成性能）

| スコア | 基準 |
|--------|------|
| 5 | 短尺 < 30 秒、中尺 < 90 秒、長尺 < 5 分 |
| 4 | 短尺 < 60 秒、中尺 < 3 分、長尺 < 10 分 |
| 3 | 短尺 < 90 秒、中尺 < 5 分、長尺 < 15 分 |
| 2 | 上記を超えるが完了する |
| 1 | タイムアウトまたは完了しない |

**判定基準**: 生成時間が現実的。

### 10. Cost Awareness（コスト意識）

| スコア | 基準 |
|--------|------|
| 5 | 1 動画あたり API コスト < $0.10 |
| 4 | $0.10〜$0.30 |
| 3 | $0.30〜$0.50 |
| 2 | $0.50〜$1.00 |
| 1 | > $1.00 |

**判定基準**: API コストが商品設計に合う。目安は無料/低価格プランで成立する範囲。

## Sprint 1〜2 自動メトリクスの読み方

生成APIが返す `generation_telemetry_summary` と `design_quality_metrics` は、手動採点の補助として使う。

| メトリクス | 見ること |
|------------|----------|
| `generation_telemetry_summary.total_calls` | 生成で何回AI APIを呼んだか |
| `generation_telemetry_summary.fallback_count` | fallbackが発生した回数 |
| `generation_telemetry_summary.total_input_tokens` / `total_output_tokens` | token使用量。取得不能な場合は null / 0 を許容 |
| `design_quality_metrics[].min_font_size_px` | HTML/CSS上の最小文字サイズ |
| `design_quality_metrics[].small_text_count` | 20px以下など小さすぎる文字の検出数 |
| `design_quality_metrics[].quality_gate` | `pass` / `warn` / `fail` の簡易判定 |

注意:
- 2026-05-02時点の実装はHTML/CSS文字列ベース。
- 画像解析による空白率・画面未使用率・content bounding boxは未実装。
- `quality_gate=pass` でも、見た目の手動QAは省略しない。

## Sprint 14追記: 補助ラベル・ページ番号・pro方向性の判定

2026-05-07のSprint 14 fixed fixture比較では、`pro` が `flash_standard` より情報設計・視線誘導・完成度で優位だった。
今後の標準方向は、単に中央へ大きなタイトルを置く構成ではなく、ステップ、チェックリスト、キーメッセージなどで情報を構造化する `pro` 寄りを優先する。

### pro方向性を採用する条件

- 3秒以内にメインメッセージが分かる。
- タイトル、サブコピー、カード本文、補助情報、装飾の優先順位が明確。
- 左から右、上から下など、見る順番が自然に設計されている。
- ステップ、チェックリスト、キーメッセージなどで情報が整理されている。
- 余白とデザイン密度のバランスがあり、リッチだが詰まりすぎていない。
- 画面全体にプロダクト感・完成度がある。

### 補助ラベルの扱い

小さい英字ラベル、section label、eyebrow、badge、meta、captionは、以下を満たす場合は装飾/補助要素として許容する。

- 読めなくてもスライドの主旨理解に支障がない。
- ブランド感、章立て感、UI的な質感を補う役割に留まっている。
- 本文・カード文・重要ラベルと混同しない。
- 小さい低コントラスト文字が多すぎてノイズになっていない。

以下に該当する場合は、補助要素ではなく主要情報として扱い、通常の可読性基準を適用する。

- 読まないと内容理解に支障がある。
- 章タイトル、手順名、チェック項目、注意事項として機能している。
- ナビゲーションや操作説明として必要。
- スライド単体で情報を完全に伝えるために必要。

### ページ番号の扱い

ページ番号は右下など一貫した位置に置く。
ただし役割で判定を分ける。

- 装飾/進行感の演出なら、小さくても許容する。
- 視聴者に現在位置を読ませるナビゲーション情報なら、通常表示サイズで読める大きさとコントラストを確保する。
- ブランド表記やフッターと混同しない配置にする。
- `02 / 02` など総ページ数を出す場合、現在ページと総ページ数の関係が明確に読めること。

### 自動メトリクスとの関係

`design_quality_metrics.small_text_count=0` は「通常本文に小さい文字がない」ことを示す。
補助ラベルやページ番号が小さいこと自体は、装飾/補助として成立していれば `quality_gate` のfail理由にしない。
ただし、手動QAでは必ず以下を確認する。

- 重要本文やカード内テキストが実表示サイズで読めるか。
- 小さい補助文字が多すぎて安っぽく見えないか。
- contact sheet、動画プレビュー、実表示サイズの3つで破綻しないか。

## 合否ライン

| 用途 | 合格ライン |
|------|-----------|
| リリース品質 | 合計 35/50 以上 かつ 全項目 3 以上 |
| 実験・比較 | 記録のみ（合否判定なし） |
| ブロッカー | いずれか1項目が 1 |

## モデル比較での使い方

1. 同一の固定音声サンプル（`docs/qa/fixtures/` 参照）を使用
2. 比較対象のモード（flash_standard / pro / image-background 等）で生成
3. 本ルーブリックで採点
4. 結果を `docs/qa/results/` に保存（テンプレート: `template-design-quality-comparison.md`）
5. 差分が大きい項目を中心に改善判断を行う
